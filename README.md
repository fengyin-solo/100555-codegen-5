# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

### 追溯码赋码与出入库扫码台账

独立一卷（`frontend/src/views/tracecode/`，数据层在 `src/data/trace-*`、服务在
`src/api/trace-service.ts`），覆盖一批码从赋码建档走到出入库核销的全链路：

- **码段按包装规格分批**：建档按「包装规格」分配连续码段（前缀+位宽+起止流水号），在档批次间码段不得重叠。
- **老次序状态流转，倒序拒收**：批次状态按
  赋码建档 → 入库中/入库完成 → 出库中/出库完成 → 核销中/已核销 → 部分退货/退货回库 序位推进；
  单码阶段 已赋码 → 已入库 → 已出库 → 已核销 → 已退货，倒序操作一律挡回。
- **客户与扫码人一一对应**：在所有在档批次间校验，一客多人 / 一人多客都拒收；出库扫码人、发货客户必须与建档绑定一致。
- **退货回库再扫一次**：已出库或已核销的码退货时必须重新扫码入账，未发出的码不能退货；回库码为末档终态，再出库须另建批次。
- **同一枚追溯码重复出库只算一次**：重复枚自动跳过并在结果中点明，出库码集合按并集去重，不重复计数。
- **赋码批次口径只留最新一版**：列表/核销默认只取每批次号最大版本；「新版建档」让旧版作废留痕，码已出库的批次不能升版。
- **核销状态两处同一套**：`trace-service.qcWriteoffRows()` 是唯一来源，追溯台账页与「成品检验」清单
  （含 CSV 导出）都按成品批号取同一结果：未核销 / 核销中 / 已核销；越界状态值由 `guardWriteoffStatus` 挡回。
- **越界 / 超限挡回**：码不属于本批次码段、阶段不对、单次扫码超过 500 枚、超过码段总量等情况整批原子挡回，不入账。
- 相关口径有 Node 自测：`cd frontend && npm test`（内存版 localStorage 桩，无需浏览器）。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。
